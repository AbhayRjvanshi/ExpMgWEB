> listed as "expected" is a planned-but-unbuilt feature, not a regression.

## Environment & Infrastructure

- [x] **Database Connection Failure (Fixed / not reproducible)**: This entry
  referred to `run_tests.php` and `db_check.php` failing with
  `mysqli_sql_exception: No connection could be made...`. MySQL now connects;
  `config/db.php` reads `DB_*` from `.env` via `config/env.php` and the full
  suite runs end to end. If it reappears, check that Apache **and** MySQL are
  running on the default ports before touching code.
- [x] **Web-accessible internals (Fixed)**: the root `.htaccess` now denies
  dotfiles, `mcp.json`, `composer.*`, `run_tests.php`, `*.sql|md|log|txt|ini|lock|jsonl`,
  and the `^(\.git|vendor|graphify-out|partials|data|logs|config|scripts|tests)(/|$)`
  paths. `vendor/`, `partials/` and `graphify-out/` carry their own
  `Require all denied` file as defence in depth.
- [x] **Test/CLI scripts reachable over HTTP (Fixed)**: `run_tests.php`,
  `tests/run_tests.php`, `tests/distributed_system_test.php`,
  `scripts/cleanup_notifications.php` and `api/workers/process_outbox.php` all
  return `403` unless `php_sapi_name() === 'cli'`.

## Features & Logic

- [x] **Inconsistent Configuration (Fixed)**: All API endpoints and core
  components use `config/db.php`, which reads `.env` through the `env()` helper.
- [x] **JavaScript Split-Brain (Fixed)**: `pages/lists.php` no longer carries an
  inline `<script>` block; it loads `public/assets/js/lists.js` (line 253).
- [x] **Durable Outbox Schema Risks (Fixed)**: `api/helpers/outbox.php` no
  longer runs brute-force `ALTER TABLE` migrations on every call.
- [x] **Unbounded notification retention on GET (Fixed)**: `api/notifications/list.php`
  and `history.php` are read-only again; retention lives in
  `scripts/cleanup_notifications.php` (7 days).
- [x] **No idempotency on writes (Fixed)**: `idempotencyGuard()` /
  `idempotencyRespond()` wrap 11 POST endpoints and `helpers.js` sends a
  per-intent `Idempotency-Key` (3-second cache).
- [ ] **Notification publisher/store never wired (KD-05)**: all producers still
  `INSERT INTO notifications` and all consumers still read MySQL.
  `notification_publisher.php`, `notification_store.php` and the
  `api/services/Notification*` backends are dead code. Needs a single migration
  of producers *and* consumers together.
- [ ] **`api/bootstrap.php` is dead code (KD-02)**: included by zero files. Its
  CSP/session hardening now lives in `config/session.php`. Either delete it or
  make it the single front-controller include — do not add it to endpoints.
- [ ] **Every `api/services/*` file is dormant (KD-11)**: `api/system/health.php`
  computes its snapshot inline; only `process_outbox.php` reaches
  `SystemOrchestrator`, and nothing outside the test suites includes the rest.
- [ ] **Business service layer absent (KD-06)**: `ExpenseService`,
  `GroupService`, `SettlementService`, `ListService`, `BudgetService`,
  `NotificationService` do not exist; logic remains in the endpoint files.
- [ ] **`schema.sql` drift (KD-12)**: missing CHECK constraints
  (`chk_expense_amount`, `chk_budget_amount`, `chk_settlement_amount`,
  `chk_item_price`, `chk_max_members`), `idx_expense_date`, and no
  `migration_v1.8.sql`. The live DB has some of these; the file does not.
